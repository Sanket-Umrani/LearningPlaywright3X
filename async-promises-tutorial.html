The mental model

JavaScript does not stop the whole program while waiting for slow work. It starts the work, keeps the main thread available, and later handles the result.

Promise states

Pending → fulfilled or rejected

A Promise is an object representing a future result. It starts pending, then settles once as either successful (fulfilled) or failed (rejected).

One useful question

What happens next?

Ask whether the operation depends on the previous result. Dependent work is usually sequential. Independent work can start together with Promise.all.

01

async

The async keyword creates an asynchronous function. Calling it always returns a Promise, even when the function returns an ordinary value.

async function getMessage() {
  return "Hello from an async function";
}

getMessage().then(console.log); // the value arrives through a Promise
Interview takeawayasync function answer() { return 42; } behaves like a function that returns a fulfilled Promise containing 42.

02

await

await pauses the surrounding async function until a Promise settles. On fulfillment it produces the value; on rejection it throws, so use try...catch when you need recovery.

async function loadUser() {
  try {
    const response = await fetch("/api/user");
    return response.json();
  } catch (error) {
    console.error("Could not load user", error);
  }
}

Important: await does not block the entire JavaScript thread. It suspends only the current async function and lets other work continue.

03

Promise.all

Use it when several independent tasks must all succeed. It waits for every input, returns results in input order, and rejects as soon as one input rejects. It does not cancel the remaining tasks.

const [profile, settings] = await Promise.all([
  getProfile(),
  getSettings()
]);

Best for

Independent requests where a missing result means the whole operation cannot continue.

Watch out

Do not pass function references. Call them: Promise.all([getProfile(), getSettings()]).

Run it: finish together, preserve order

The fast task finishes first, but the result array keeps the order you supplied.

04

Promise.race

Use it when the first task to settle wins. “Settle” includes both fulfillment and rejection, so a fast failure can win the race. Losing work is not automatically cancelled.

const result = await Promise.race([
  fetchData(),
  timeout(3000)
]);
Classic use caseRace a network request against a timeout. For real cancellation, pair the request with AbortController.

Run it: the fastest settlement wins

Two timers start together. The 500 ms timer wins.

05

new Promise

The Promise constructor is mainly a bridge for callback-style APIs. Its executor runs immediately and receives resolve and reject functions.

function wait(ms) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(`Waited ${ms} ms`), ms);
  });
}

wait(400).then(console.log);
Rule of thumbDo not wrap an API that already returns a Promise. Create a new Promise when you need to adapt callbacks or control an external completion event.
06

Callback

A callback is a function passed to another function so it can be invoked later. Callbacks can be synchronous, like array.map(), or asynchronous, like a timer callback.

function getOrder(callback) {
  setTimeout(() => {
    callback(null, { item: "Coffee", ready: true });
  }, 400);
}

getOrder((error, order) => {
  if (error) return console.error(error);
  console.log(order);
});

Strength

Simple APIs and direct control over what happens after an operation finishes.

Cost

Many dependent callbacks can create nested code and scattered error handling. Promises make composition easier.
