Terminal confidence

Linux commands for QA.

A practical command map for navigating test environments, checking services, reading logs, calling APIs, and collecting evidence without leaving the terminal.

QA habitKnow where you are, inspect before changing, capture the exact command and output, then clean up what you created.
01

Move around and manage test files

Navigate

Confirm the current directory before running a path-sensitive test.

pwd # current path ls -la # all files + details cd /var/log # change directory cd - # previous directory

Create and inspect

Use small files to reproduce a test condition or preserve a request payload.

mkdir -p test-data touch payload.json cat payload.json less application.log

Copy, move, remove

Be deliberate with destructive operations in shared environments.

cp app.log backup.log mv old.json archive/ rm -i temp.txt find . -name "*.log"
02

Search failures and understand output

Search logs with context

Filter noise, keep nearby lines, and count recurring failures.

grep -in "error" application.log grep -in -C 3 "timeout" application.log grep -Rin "failed" ./test-results/ grep -ic "500" access.log

Head, tail, follow

Useful for startup checks and watching a running test.

head -n 30 app.log tail -n 50 app.log tail -f app.log

Pipe the evidence

Send one command's output into another command.

ps aux | grep node cat results.txt | wc -l history | tail
03

Check processes, ports, and permissions

Is the service alive?

Identify processes and inspect the port your test depends on.

ps aux | grep app pgrep -af node ss -tulpn lsof -i :3000

Permissions

Read access failures before changing anything. Avoid broad chmod in shared systems.

ls -l test.sh chmod u+x test.sh ./test.sh whoami

Resources

Slow tests can be environment problems, not product failures.

df -h # disk free -h # memory top # live usage
04

Network and API smoke checks

curl: fast endpoint evidence

Keep headers, status codes, and response bodies visible in a repeatable command.

curl -I https://qa.example.com/health curl -sS -o response.json -w "%{http_code}" https://qa.example.com/api/users curl -X POST -H "Content-Type: application/json" -d @payload.json https://qa.example.com/api/login

Reachability

Separate DNS or network failures from application failures.

ping -c 4 qa.example.com nslookup qa.example.com curl -v https://qa.example.com

Download a test artifact

Preserve a build, report, or fixture for later inspection.

wget URL curl -O URL sha256sum report.zip
